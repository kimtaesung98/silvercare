# 대화 루프 명세 (단계 3)

> 기준일: 2026-10-06. 닫힌 PR #1(NestJS 대화 루프)의 동작과 테스트 케이스를 Go 서버 단계 3으로 옮기기 위한 명세입니다.
> 전체 흐름은 [architecture.md](../architecture.md) 6.1절을 따르고, 이 문서는 그중 **어르신 발화 한 건을 처리하는 규칙**과 **반드시 통과해야 하는 테스트 케이스**만 정합니다.
> PR #1의 원본 코드는 PR #1 브랜치(`refs/pull/1/head`, `backend/src/modules/session/session.service.ts`, `*.spec.ts`)에서 볼 수 있습니다.
> Go 구현은 `server/internal/session`(엔진), `internal/escalation`(규칙), `internal/llm`(프롬프트)이고 4절 테스트는 `internal/session/engine_test.go`, `internal/escalation/rules_test.go`입니다.

## 1. 발화 한 건의 처리 순서

1. 입력 텍스트(STT 결과)의 앞뒤 공백을 제거합니다. 비어 있으면 거부합니다.
2. 세션이 없으면 거부합니다(없음). 이미 끝난 세션(`ended_at` 있음)이면 거부합니다. 두 경우 모두 `utterance`를 저장하지 않습니다.
3. **규칙 필터를 먼저** 돌립니다. Claude 호출 여부와 상관없이 모든 발화에 항상 실행합니다.
4. 어르신 발화를 `utterance`(ELDER)로 저장합니다. 규칙에 걸렸으면 `flagged_risk = true`입니다.
5. 규칙에 걸린 경우
   - 저장한 발화 ID로 `escalation_event`를 만듭니다 (`source = RULE`, `rule_id` 기록).
   - **Claude를 부르지 않고** 고정 안심 문장을 응답으로 씁니다.
6. 걸리지 않은 경우
   - 시스템 프롬프트: 어르신 이름 + 관심사 상위 5개 키워드 (기존 `buildSystemPrompt` 내용 유지).
   - 메시지: 세션의 모든 발화를 시간순으로 변환합니다. ELDER는 `user`, AI는 `assistant`.
     첫 발화가 AI 인사말이므로 맨 앞에 시작 지시문(`user`)을 붙이고, 같은 화자가 연달아 말한 발화는 줄바꿈으로 합쳐 한 턴으로 만듭니다.
   - Claude 호출이 실패하거나 빈 텍스트가 오면 대체 문장을 응답으로 씁니다. 오류는 로그로 남기고 요청은 실패시키지 않습니다.
7. 응답을 `utterance`(AI)로 저장하고 다음을 돌려줍니다: 어르신 발화 ID, AI 발화 ID, 응답 텍스트, 위급 여부, 감지 유형(없으면 null).

> 단계 3에서는 6번의 단일 응답이 0번 문장 + 스트리밍 문장(1, 2, 3…)으로 바뀝니다. 위 순서 중 1~5번과 대체 문장 규칙은 그대로 유지합니다.

## 2. 고정 문장

| 용도 | 문장 |
| --- | --- |
| 시작 지시문 (프롬프트 전용) | 대화를 시작해줘. 노인에게 먼저 친근하게 인사하고 관심사 화제를 자연스럽게 꺼내줘. |
| 위급 감지 시 안심 문장 | 지금 많이 힘드시죠. 선생님께 바로 알려드렸어요. 조금만 기다려주세요. |
| Claude 실패·빈 응답 시 대체 문장 | 네, 말씀 잘 들었어요. 선생님이 곧 오실 거예요. 조금만 더 저랑 이야기 나눠요. |

## 3. 규칙 필터

| 유형 | 패턴 |
| --- | --- |
| `FALL_MENTION` | `넘어졌`, `쓰러졌`, `낙상` |
| `PAIN_COMPLAINT` | `아파`(뒤에 `트`가 오면 제외), `아프`, `통증`, `숨이 차`(공백 0개 이상) |
| `SELF_OR_OTHER_HARM` | `죽고 싶`(공백 0개 이상), `자해`, `때리` |

위에서부터 검사해 처음 걸린 유형 하나를 씁니다. 목록은 초안이며 단계 7에서 전문가 검토를 받습니다.
Go의 `regexp`(RE2)는 `(?!트)` 같은 부정 전방탐색을 지원하지 않으므로, `아파트`를 먼저 제외하고 검사하는 식으로 구현합니다.

## 4. 테스트 케이스 (Go로 옮겨 통과해야 함)

### 4.1 규칙 필터

감지돼야 하는 문장:

| 문장 | 유형 |
| --- | --- |
| 아까 화장실에서 넘어졌어 | `FALL_MENTION` |
| 길에서 쓰러졌었지 | `FALL_MENTION` |
| 다리가 너무 아파 | `PAIN_COMPLAINT` |
| 머리가 아프네 | `PAIN_COMPLAINT` |
| 숨이 차서 힘들어 | `PAIN_COMPLAINT` |
| 그냥 죽고 싶어 | `SELF_OR_OTHER_HARM` |
| 누가 나를 때리려고 해 | `SELF_OR_OTHER_HARM` |

감지되면 안 되는 문장:

- 오늘 날씨가 좋네
- 손주가 어제 놀러 왔어
- 우리 아파트 앞에 꽃이 폈어

위급 이벤트 생성 시 세션 ID, 발화 ID, 유형이 기록돼야 합니다.

### 4.2 발화 처리

| # | 상황 | 기대 결과 |
| --- | --- | --- |
| 1 | 평범한 발화 `"  손주가 어제 왔어 "` | 공백 제거된 텍스트로 필터 검사·저장(`flagged_risk=false`). Claude 요청의 시스템 프롬프트에 어르신 이름과 관심사 키워드 포함, 메시지 역할 순서 `user, assistant, user`, 마지막 메시지는 `손주가 어제 왔어`. 응답이 AI 발화로 저장되고 위급 이벤트 없음 |
| 2 | 위급 발화 `화장실에서 넘어졌어` | ELDER 발화 `flagged_risk=true`, 그 발화 ID로 `FALL_MENTION` 위급 이벤트 생성, Claude 호출 없음, 응답은 안심 문장 |
| 3 | 기록이 AI 인사 → ELDER `응` → ELDER `오늘 날씨 좋네` | Claude 메시지 3개, 마지막은 `user: "응\n오늘 날씨 좋네"` |
| 4 | Claude 호출 오류 | 대체 문장으로 응답하고 AI 발화로 저장, 위급 아님, 요청은 성공 |
| 5 | Claude가 텍스트 없이 응답 | 대체 문장으로 응답 |
| 6 | 텍스트가 공백뿐 | 잘못된 요청으로 거부, 발화 저장 없음 |
| 7 | 없는 세션 ID | 없음으로 거부 |
| 8 | 이미 끝난 세션 | 잘못된 요청으로 거부, 발화 저장 없음 |
