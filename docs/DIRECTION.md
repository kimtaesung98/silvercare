# 실버케어 방향 문서

> 처음 만든 날: 2026-10-18. 모든 회차는 이 문서를 읽고 시작하고, 이 문서에 한 줄 남기고 끝냅니다.
> 1~5절은 주인이 확인한 내용만 고칩니다. 6~7절은 에이전트가 회차마다 채웁니다.

## 1. 왜 만드나

노치원(주간보호센터)에 다니는 어르신은 조무사가 데리러 오기 전, 그리고 집에 돌아온 뒤 혼자 기다리는 시간이 깁니다.
이 시간에 **태블릿 속 말동무가 어르신과 이야기**하고, 그 이야기에서 알게 된 것을 **조무사와 보호자에게 전해** 사람이 더 잘 돌볼 수 있게 합니다.

| 누구 | 무엇을 얻나 |
| --- | --- |
| 어르신 (가장 먼저) | 기다리는 시간이 덜 외롭고 덜 불안함. 기계를 만질 필요 없이 말로만 |
| 조무사 | 도착 전에 어르신 상태를 짧은 브리핑으로 앎. 위급하면 바로 알림 |
| 보호자 | 태블릿을 켜 두고 맡겨 둘 수 있음 (켜고 떠나면 끝). 하루 소식과 위급 알림 |
| 센터 | 어르신 한 분 한 분을 더 잘 앎 |

## 2. 북극성

> 어르신이 태블릿에 말을 걸면 곧바로 따뜻한 목소리가 대답하고, 위급한 말은 놓치지 않고 사람에게 전해진다.

회차 목표를 고를 때 "이게 북극성에 얼마나 가까워지게 하나"를 먼저 묻습니다.

## 3. 지키는 원칙

바꾸려면 주인에게 먼저 묻습니다.

1. **안전이 먼저**: 위급한 말은 규칙 필터가 Claude보다 먼저 잡고, Claude의 판단은 2차입니다.
2. **어르신 눈높이**: 큰 글씨, 말로만 쓰기, 기다리는 느낌 줄이기(0번 문장처럼 바로 맞장구).
3. **사람을 대신하지 않음**: 말동무는 사람이 올 때까지 곁을 지키고, 알게 된 것을 사람에게 넘깁니다.
4. **Claude는 서버에서만** 부릅니다. 키가 기기에 남지 않고 안전 필터를 건너뛸 길이 없게.
5. **키가 없어도 돈다**: 외부 서비스가 없거나 실패하면 대체 동작으로 흐름이 끊기지 않게.
6. **개인정보 조심**: 대화가 시작되기 전 들린 말은 서버로 보내지 않고, 보관은 국내 리전을 기본으로.

## 4. 구조: 채팅이 바탕, 그 위에 모듈

이 서비스는 기본적으로 **카카오톡 같은 채팅**입니다. 대화방이 있고, 참가자가 있고, 메시지가 오갑니다.
그 위에 **참가자가 사람인지 AI인지**를 붙이고, 필요한 기능을 모듈로 덧붙여 서비스를 만듭니다.

```
 [서비스]   픽업 대기 · 말동무 · 하루 소식 · 브리핑 …   ← 방을 열고 참가자를 넣는 규칙
 [모듈]     위급 필터 · 음성(STT/TTS) · 요약 · ETA …     ← 메시지를 보고 끼어들거나 덧붙임
 [참가자]   어르신 · 조무사 · 보호자 (사람)  /  말동무 AI ← 같은 방식으로 방에 들어옴
 [바탕]     대화방 · 참가자 · 메시지 · 실시간 전달        ← 카카오톡과 같은 채팅
```

- **바탕(채팅)** 은 서비스 내용을 모릅니다. 방, 참가자, 메시지, 실시간 전달만 합니다.
- **참가자** 는 사람이든 AI든 같은 방식으로 방에 들어와 메시지를 읽고 씁니다. AI를 다른 AI나 사람으로 바꿔 끼워도 바탕은 그대로입니다.
- **모듈** 은 방에 오가는 메시지를 보고 동작합니다. 위급 필터는 메시지를 먼저 보고 사람에게 알리고, 음성 모듈은 말을 글로, 글을 말로 바꿉니다. 모듈은 켜고 끌 수 있고, 하나를 빼도 나머지가 돕니다.
- **서비스** 는 언제 어떤 방을 열고 누구를 넣을지 정하는 규칙입니다. 예: 조무사가 15분 안에 오면 어르신·말동무 AI 방을 열고, 도착하면 조무사가 방에 들어와 브리핑을 봅니다.
- 새 기능을 만들 때 먼저 묻습니다: "이건 바탕인가, 참가자인가, 모듈인가, 서비스인가?" 바탕은 가능한 한 작고 단단하게 둡니다.

## 5. 주인이 원하는 개발 방식

- **회귀 방식**: 짧은 회차를 반복합니다. 회차마다 이 문서로 돌아와 목적을 다시 확인하고 시작합니다.
- **문제 지적보다 새 방향과 적극성**: 막히면 원인만 오래 파지 말고, 목적에 닿는 다른 길을 제안하고 직접 시도합니다. 문제는 한 줄로 기록하고 넘어갑니다.
  예: 에뮬레이터 마이크가 고정 신호(RMS 0.706)만 줄 때는 실기기, 텍스트 대화, 녹음 파일 주입처럼 다른 길로 대화를 먼저 살립니다.
- **되돌릴 수 있는 일은 묻지 않고 합니다**: 브랜치, 초안 PR, 실험 코드. 목적·원칙·구조(1~4절)를 바꾸거나 되돌릴 수 없는 일만 묻습니다.
- **화면 먼저, 그다음 기능 (피그마)**: 화면은 피그마에서 먼저 그리고, 그 화면을 기준으로 기능을 붙이고 강화합니다. 피그마 화면이 기준이고, 코드의 화면은 그것을 따라갑니다. 화면에 없는 기능을 만들어야 하면 먼저 어떤 화면이 필요한지 제안합니다.
- **회차마다 손으로 만져볼 것 하나**: 문서나 리팩터링만으로 끝내지 않고, 주인이 실제로 돌려 볼 수 있는 변화 하나를 남깁니다.
- **쉬운 한국어**: 문서와 답은 한국어로, 전문 용어는 처음 나올 때 풀어 씁니다.

## 6. 한 회차 진행법

1. 이 문서 1~5절과 7절의 지난 기록을 읽습니다.
2. 이번 회차 목표를 하나 고르고, 그 목표의 피그마 화면을 확인합니다. 화면이 없으면 필요한 화면을 제안하고 그 화면부터 정합니다.
   목표는 북극성에 가까워지는 것, 그리고 주인이 정한 목표가 없으면 에이전트가 제안한 다음 방향 중 하나.
3. 화면에 맞춰 만들고, 실제로 돌려 확인합니다 (`cd v2 && go test -race ./...`, 브라우저나 기기에서 직접).
4. 7절에 한 줄을 남깁니다: 한 것, 알게 된 것, **다음에 시도할 새 방향 하나**.
5. 목적이나 원칙과 부딪히면 멈추고 주인에게 묻습니다.

## 8. 출발점과 참고 자료

2026-10-18 주인 결정: **새로 처음부터** 만듭니다.

- 새 코드는 저장소 루트의 `v2/` 폴더에 만듭니다.
- `notchiwon-bridge/`는 고치지 않는 참고 자료입니다. 필요한 생각이나 코드 조각은 가져오되, 그대로 옮기지 않고 이번 회차 목표에 맞는 만큼만 가져옵니다.
- 기술 스택도 회차에서 다시 고를 수 있습니다. 바꿀 이유가 없으면 이전과 같이 Go 서버와 Flutter 앱으로 갑니다.
