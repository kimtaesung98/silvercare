# 하위 명세: 듣기 (귀)

> **이름 주의**: 이 부품은 소리를 **녹음해 저장하지 않습니다**. 마이크로 들은 말을 글(또는 잠깐 메모리에 든 소리 구간)로 바꿔 바로 넘기는 "듣기"입니다. 앱 기능 목록에 "녹음" 기능은 없습니다. 이전 이름 "녹음기(recorder)"는 쓰지 않습니다.

> 묶음: [mid/voice.md](../../mid/voice.md) · 상태: 초안 (쌍둥이 시험 1회 뒤 보강) · 고친 날: 2026-11-02
> 위층: VOICE-01 ~ VOICE-08, VOICE-10
> 만들 곳: `v2/apps/elder_tablet/lib/src/voice/` · 언어와 플랫폼: Flutter (Dart), Android 태블릿 (Android 10 이상)
> 쌍둥이 시험 기록: [../../twin-tests/listener-1.md](../../twin-tests/listener-1.md). 2026-11-02 보강한 줄은 `(T1)`로 표시합니다.

## 1. 목적

어르신 태블릿에서 마이크를 열고, 어르신의 말 한 마디가 시작되고 끝나는 때를 찾아, 그 말을 **글**(기기 인식 방식) 또는 **소리 구간**(서버 인식 방식)으로 하나씩 내보냅니다. 듣는 상태를 바뀔 때마다 알려 마이크 원이 따라 움직이게 합니다.

## 2. 경계

- 한다: 마이크 권한 확인, 마이크 열고 닫기, 소리 세기 재기, 말 시작·끝 찾기, 들은 말 내보내기, 이상 신호 알아채기, 실패 뒤 다시 해 보기, 서버 방식에서 기기 방식으로 바꾸기.
- 하지 않는다:
  - 대화방에 보내기 → 태블릿 대화 흐름 (`ElderController`).
  - 소리 들려주기 → 재생 순서 (`low/voice/playback.md`). 듣기는 "쉬기"·"다시 듣기" 명령만 받습니다.
  - 위급 판단, 말 거르기 → 서버 (`mid/safety`). 듣기는 길이 0.4초 미만만 버립니다.
  - 마이크 원 그리기 → 화면 (`mid/elder-tablet`). 듣기는 상태만 내보냅니다.
  - 서버 인식 실패 세기 → 대화 흐름. 3번 이어지면 대화 흐름이 듣기에 `기기 방식으로 바꾸기`를 부릅니다.
- **일 나누기 (T1)**: 서버 방식에서 말 구간 자르기 부품은 배경 소리, 시작·끝 문턱, 무음 끝 0.9초, 최소 길이 0.4초를 맡습니다. 듣기는 이상 신호 판정, 최대 길이 30초, 쉬기·방식 바꾸기 때 끊기를 맡습니다. `low/voice/segmenter.md`가 쓰이기 전까지는 이 명세 5절과 5-1절이 자르기 부품의 동작입니다.

## 3. 상태

| 상태 | 들어오는 조건 | 나가는 조건 → 다음 상태 | 이 상태에서 하는 일 |
| --- | --- | --- | --- |
| 꺼짐 | 처음, 또는 `멈춤` | `시작` → 기다림 (권한·마이크 문제면 못 씀) | 마이크 닫음. 아무것도 내보내지 않음 |
| 기다림 | `시작` 성공, 말 하나를 내보낸 뒤, `다시 듣기` 뒤 0.3초 | 말 시작을 찾음 → 듣는 중 / `쉬기` → 쉼 / 마이크 오류 → 못 씀 | 마이크 열림. 소리 세기 내보냄. 배경 소리 잼(서버 방식) |
| 듣는 중 | 말 시작 | 말 끝 → (말 내보냄) → 기다림 / 최대 길이 → (내보냄) → 기다림 / `쉬기` → (지금까지 들은 것을 내보냄) → 쉼 / 오류 → 못 씀 | 말을 모음. 소리 세기 내보냄 |
| 쉼 | `쉬기` (말동무 소리가 나는 동안) | `다시 듣기` → 0.3초 뒤 기다림 / `멈춤` → 꺼짐 | 마이크로 들어오는 소리를 쓰지 않음. 끼어들기를 켰을 때만 듣는 중으로 갈 수 있음 (LIS-12) |
| 못 씀 | 권한 없음, 마이크 열기 실패, 이상 신호, 기기 인식기 없음 | 5초마다 다시 해 보고 성공 → 기다림 / `멈춤` → 꺼짐 | 이유를 함께 내보냄 |

처음 상태는 **꺼짐**입니다. 어느 상태에서든 `멈춤`을 받으면 마이크를 닫고 꺼짐으로 갑니다.

### 3-1. 표에 없는 옮겨 가기 (T1)

| 경우 | 하는 일 |
| --- | --- |
| 기다림에서 `쉬기` | 아무것도 내보내지 않고 쉼 |
| 쉼에서 `쉬기` | 상태 그대로. 기다리던 `다시 듣기`(0.3초)가 있으면 거둠 |
| 0.3초를 기다리는 중 `다시 듣기` | 무시. 처음 잰 0.3초 그대로 |
| 0.3초 동안 | 상태는 쉼. 그동안 들어온 소리 조각은 버림. 0.3초가 지나면 자르기 부품은 **조용한 조각을 기다리지 않고** 바로 말 시작을 찾음 (원칙 1. 가정 A-R-05) |
| `멈춤`이나 못 씀으로 갈 때 듣던 말 | 버림. 내보내지 않음 |
| 못 씀으로 갈 때 | 마이크를 닫고 인식기를 멈춤 |
| 다시 해 보기 | 이유와 관계없이 켜기를 처음부터: 권한 확인 → (기기 방식) 인식기 있는지 확인 → (서버 방식) 마이크 열기. 못 씀에 들어간 때부터 5초 뒤 첫 시도, 실패하면 다시 5초 뒤 |
| 이상 신호가 이어짐 | 다시 해 보기는 마이크를 다시 열면 성공(기다림). 고정 신호가 계속되면 2.9초 뒤 다시 못 씀. 그래서 약 8초마다 기다림 → 듣는 중 → 못 씀이 되풀이됨 (그대로 둠) |
| 고정 신호로 듣는 중이 됨 | 고정 신호(0.706)는 시작 문턱을 넘으므로 기다림 → 듣는 중 → 못 씀(이상 신호) 순서. 모은 소리는 버림 |
| 마이크 흐름이 오류를 내거나 열린 채 끝남 | 못 씀(사용 중) |
| 서버 방식 쉼 | 마이크는 열어 둠. 끼어들기를 껐으면 조각을 자르기 부품에 넣지 않음 (배경 소리도 따라가지 않음) |
| 기기 방식 쉼 | 인식기를 멈춤. 끼어들기를 켰으면 새 한 번 듣기를 켜 둠. `다시 듣기` 0.3초 뒤 인식기를 다시 켬 |
| 기기 방식, 한 번 듣기가 끝남 | 마지막 글 뒤에는 곧바로 다시 켬. 오류(인식 실패, 말 없음)나 흐름이 그냥 닫힌 뒤에는 1초 쉬고 다시 켬 (곧바로 실패하는 인식기가 쉼 없이 돌지 않게. 가정 A-R-06) |
| 기기 방식, 듣는 중으로 가는 때 | "말 시작됨" 또는 비지 않은 첫 "중간 글" 중 먼저 오는 것 |
| 인식기가 없는 기기에서 `시작(기기)` | 마이크 자리가 있으면 못 씀을 내지 않고 서버 방식으로 기다림. 없으면 못 씀(인식기 없음). 단 `기기 방식으로 바꾸기`를 받은 뒤에는 서버로 돌아가지 않음 |
| 마이크 자리가 없는데 `시작(서버)` | 기기 방식으로 켬 (VOICE-05) |
| 켜는 중(권한 확인 기다림)에 `멈춤` | 늦게 끝난 켜기 결과는 버림. 그사이 마이크가 열렸으면 바로 닫음 |

### 3-2. 기기 방식으로 바꾸기 (LIS-09, T1)

| 지금 상태 | 하는 일 | 내보내는 상태 |
| --- | --- | --- |
| 꺼짐 | 아무것도 안 함 | 없음 |
| 이미 기기 방식 | 아무것도 안 함 | 없음 |
| 기다림 | 마이크 닫고 인식기 켬 | 없음 (기다림 그대로) |
| 듣는 중 | 지금까지 모은 소리 구간을 곧바로 소리 들은 말로 내보냄(0.4초 이상일 때). 마이크 닫고 인식기 켬 | 듣는 중 → 기다림 |
| 쉼 | 마이크 닫음. `다시 듣기` 0.3초 뒤 인식기를 켬 | 없음 |
| 못 씀 | 기다리던 다시 해 보기를 거두고 기기 방식으로 바로 다시 해 봄 | 결과에 따라 |

바꾼 뒤 서버 방식으로 돌아가는 명령은 없습니다. 다음 `시작`이 방식을 새로 정합니다. 이미 들은 소리를 Android 인식기에 다시 넣을 수는 없으므로, "버리지 않음"은 위처럼 소리 구간을 그대로 내보낸다는 뜻입니다.

- 모든 기대 부품은 가짜로 바꿀 수 있어야 합니다. 가짜 마이크는 **녹음 파일(WAV, 6절 형식)** 을 소리 조각으로 흘려보낼 수 있어야 하고, 가짜 기기 인식기는 정해 둔 글을 정해 둔 때에 돌려줄 수 있어야 합니다. 가짜 부품의 자세한 동작은 11-1절.
- 말 구간 자르기 부품은 서버 방식을 켤 때마다 새로 만듭니다 (배경 소리도 처음부터).
- 기기 인식기 오류와 상태 (T1): 인식기 없음 → 못 씀(인식기 없음), 권한 없음 → 못 씀(권한 없음), 마이크 사용 중 → 못 씀(사용 중), 인식 실패·말 없음 → 기다림.
- 기기 방식에서는 마이크 자리를 열지 않습니다 (Android 인식기가 마이크를 직접 씀). 그래서 기기 방식의 소리 세기와 이상 신호는 인식기가 주는 소리 세기에만 기댑니다.
- 기기 방식 소리 세기: 인식기 값(Android `onRmsChanged`, 대략 −2~10 dB)을 `(값 + 2) ÷ 12`로 바꾸고 0~1로 자릅니다. 범위 −2·10은 설정값입니다. 0.1초마다 마지막 받은 값을 냅니다. 값을 한 번도 받지 못했으면 듣는 중에 0.5, 기다림에 0을 냅니다 (T1).
- 끼어들기를 켜고 끄는 것은 듣기를 만들 때 정하는 설정값입니다 (기본 끔). 에코 제거가 확실한지는 켜는 쪽이 판단합니다.
- 이름은 만드는 쪽이 정해도 됩니다. 다만 Flutter의 `Listener` 위젯과 겹치지 않게 `VoiceListener`를 추천합니다. 말 길이는 초(소수)로 냅니다.

### 5-1. 숫자를 쓰는 법 (T1)

- **말 시작**: 시작 문턱 이상인 조각 **하나**로 곧바로 듣는 중. 확인 창이나 앞쪽 여유 조각(pre-roll)은 없음. 소리 구간은 그 조각부터.
- **말 끝**: 끝 문턱 미만 조각이 9개 이어지면 끝. 그사이 끝 문턱 이상 조각이 오면 다시 셈.
- **배경 따라가기**: 말 밖(기다림, 끼어들기를 켠 쉼)의 조각마다 `배경 ← 배경 + (세기 − 배경) × (1 − e^(−0.1/τ))`. 세기가 배경보다 작으면 τ = 0.1초, 크면 τ = 1.0초. 처음 배경은 0. 한 조각에서 시작 판정을 먼저 하고, 말 시작이 아니면 그 조각으로 배경을 고침.
- **말 길이 (서버 방식)**: 말 시작 조각부터 끝 문턱 이상인 마지막 조각까지. 끝의 무음은 길이에도 소리 구간에도 넣지 않음. 무음을 넣으면 0.2초 기침도 1.1초가 되어 0.4초 규칙이 뜻을 잃음.
- **말 길이 (기기 방식)**: 인식기가 길이를 주면 그것. 아니면 말 시작부터 마지막으로 중간 글이 바뀐 때까지. 중간 글이 없으면 (마지막 글이 온 때 − 무음 끝 기준). 0보다 작으면 0.
- **말 시작을 못 본 채 기기 방식 마지막 글이 옴**: 길이를 잴 수 없으므로 길이 0으로 적고 **0.4초 규칙을 적용하지 않고** 내보냄 (원칙 1, 위급한 말을 놓치지 않게).
- **쉬기·방식 바꾸기로 끊은 말**: 서버 방식은 지금까지 모은 소리에서 끝의 무음을 뺀 것(위 말 길이와 같은 규칙). 기기 방식은 마지막으로 받은 비지 않은 중간 글을 곧바로 내보내고 인식기를 멈춤, 길이는 말 시작부터 `쉬기`까지. 중간 글이 없으면 아무것도 내보내지 않음. 늦게 오는 마지막 글은 버림. 0.4초 규칙은 여기에도 씀.
- **최대 길이**: 서버 방식은 듣기가 말 시작 조각부터 300번째 조각에서 끊어 내보냄(정확히 960,000바이트). 상태는 듣는 중 → 기다림이고, 말이 이어지면 다음 조각에서 다시 듣는 중. 기기 방식은 인식기에 30초를 넘기기만 하고 따로 재지 않음.
- **이상 신호 창**: 기다림·듣는 중의 조각만 넣고, 30개가 다 찬 뒤 조각마다 판정. 마이크를 열 때, `쉬기`, `다시 듣기`, 끼어들기 때 창을 비움. 그래서 고정 신호의 첫 조각이 들어온 때부터 2.9초 뒤(30번째 조각)에 못 씀. 기기 방식은 인식기 소리 세기를 0.1초마다 창에 넣어 같은 기준으로 판정하고, 값을 주지 않는 인식기면 판정하지 않음.
- **조각 크기**: 마이크 자리가 3,200바이트가 아닌 덩이를 주면 듣기가 3,200바이트로 다시 묶고 남은 바이트는 다음 덩이에 붙임.
- **소리 세기 값 (서버 방식)**: 0.1초 타이머 때의 마지막 조각 소리 세기. 아직 조각이 없으면 0.

## 7. 플랫폼

- 권한: `RECORD_AUDIO`. 권한은 보호자가 처음 설정에서 허용합니다 (`mvp.md` MVP-C-05). 듣기는 권한을 **요청하지 않고 확인만** 합니다. 없으면 못 씀(권한 없음).
- 화면이 꺼져도 듣기: Foreground Service, 종류 `microphone` (Android 14 이상에서 필수). 알림 문구 "말동무가 듣고 있어요".
- 기기 인식기: Android `SpeechRecognizer`, 언어 `ko-KR`(설정값). 지금은 `speech_to_text` 패키지로 씁니다 (`v2/apps/elder_tablet/lib/src/voice.dart`). 인식기가 없을 때는 3-1절.
- 마이크(서버 방식): `record` 패키지의 PCM 흐름 (이전 버전 `notchiwon-bridge/app/packages/voice`에서 쓴 것). 고른 이유: 16kHz PCM 흐름을 바로 주고 Android·iOS 모두 됨.
- 알려진 문제: 기기 인식기를 다시 켤 때마다 Android가 "띵" 소리를 낼 수 있음 (이전 리뷰 `notchiwon-bridge/docs/handbook/code-review.md`). 열린 질문 Q-R-02.

## 9. 개인정보와 안전

- 듣기는 `시작` 전과 `멈춤` 뒤에 마이크를 열지 않습니다. 대화 흐름은 대화방이 열린 뒤에만 `시작`을 부릅니다 (VOICE-01).
- 소리를 파일로 저장하지 않습니다. 소리 구간은 내보낸 뒤 듣기 안에 남기지 않습니다 (VOICE-08). 핵심 코드는 파일 쓰기 라이브러리(`dart:io`)를 가져오지 않는 것을 추천합니다.
- 기기 방식에서 Android 인식기가 소리를 기기 밖(구글 서버)으로 보낼 수 있습니다. 열린 질문 Q-R-04.
- 들은 말을 거르지 않습니다. 길이 0.4초 미만만 버리고, 길이를 모르면 버리지 않습니다 (위급한 말을 놓치지 않게, 원칙 1).
