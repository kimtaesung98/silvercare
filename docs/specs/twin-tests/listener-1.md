## 4. 둘이 따로 같은 답을 낸 곳 (명세에 옮겨 적음)

명세가 정하지 않았는데 두 쪽이 같은 길을 고른 곳입니다. 다음 에이전트가 다르게 고를 수 있어 그대로 적었습니다.

- 명령 `기기 방식으로 바꾸기`가 4절 표에 없음 → 둘 다 더함 (4절, 3-2절).
- LIS-09 "그사이 들은 말은 기기 방식으로 다시 듣는다"는 글자 그대로는 불가능 (Android 인식기에 소리를 다시 넣을 수 없음) → 둘 다 "듣던 소리 구간을 내보내고 다음 말부터 기기 방식"으로 읽음 (LIS-09 고침).
- 서버 방식 말 길이는 끝 무음을 뺌. 넣으면 0.2초 기침이 1.1초가 되어 AC-03이 성립하지 않음.
- 기기 방식 쉬기 때 "듣던 말" = 마지막 중간 글.
- 기기 방식에서는 마이크 자리를 열지 않음. 그래서 기기 방식에서 WAV 시험은 할 수 없고 가짜 인식기 대본으로 시험함.
- 기기 인식기 출력에 소리 세기와 "있는지 확인"이 필요함.
- 말 구간 자르기에 "지금 끊기", "비우기"가 필요함.
- `멈춤`·못 씀 때 듣던 말은 버림. 0.4초는 경계 포함 내보냄. 이상 신호는 첫 고정 조각 뒤 2.9초. 고정 신호가 이어지면 약 8초마다 못 씀이 되풀이됨.

## 5. 명세끼리 어긋난 곳

- `mid/voice.md` AC-V-03은 상태 순서를 "기다림 → 듣는 중 → 쉼 → 기다림"이라 했지만, 듣기 3절대로면 말을 내보낸 뒤 기다림으로 가므로 "기다림 → 듣는 중 → 기다림 → 쉼 → 기다림"입니다. AC-V-03을 고쳤습니다.
- 배경 소리를 누가 재는지 2절(자르기 부품)과 3절(듣기)이 어긋났습니다. 2절에 일 나누기를 적었습니다.
